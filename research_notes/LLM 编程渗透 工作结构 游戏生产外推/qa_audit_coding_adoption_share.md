# QA audit: coding_adoption_penetration.md and ai_code_share_productivity.md

## Header

- **Scope.** Independent fact-check of the two notes named above (Nov 2022 → Sep 2026 coding-adoption, AI share of code, productivity evidence, capability trajectory, China). Other notes in the folder were grepped for overlap; they contain no overlapping coding facts (only game-industry material), so cross-note checks are between these two notes.
- **Date.** 2026-09-28.
- **Method.** (1) Both notes read in full. (2) ~90 load-bearing quantitative claims extracted. (3) Verified against primary pages on the fetchable domains (microsoft.com investor pages FY23Q2–FY26Q4, anthropic.com, claude.com, cloud.google.com, github.com), against ~70 WebSearch queries (quota held throughout), and by re-running the notes' own GitHub search-API counts through the GitHub MCP tool. (4) Status codes: **VERIFIED** (primary page fetched, or ≥2 independent credible secondary sources agreeing on the same wording), **VERIFIED-S** (search-snippet/secondary only, consistent), **CORRECTED**, **DISPUTED**, **UNVERIFIABLE**.
- **Limits.** Egress-blocked this session: survey.stackoverflow.co, stackoverflow.blog, blog.jetbrains.com, github.blog, metr.org, thenewstack.io, dora.dev, gartner.com, openai.com, all Chinese sites, resources.anthropic.com (Anthropic's PDF host). For those, "VERIFIED-S" relies on search-engine snippets of the primary page (the snippets quote the page, but decimals and bases should be spot-checked; see VERIFICATION QUEUE). Direct api.github.com is blocked for curl; the GitHub MCP search tool works but returns 502/504 intermittently and is secondary-rate-limited (~10 queries/min).
- **Tag convention in this audit.** [F] fetched primary page this session; [S] search-snippet/secondary; [M] measured via GitHub MCP search this session.

## Overall verdict per note

**coding_adoption_penetration.md (Note A).** Reliable on everything sourced to Microsoft earnings pages, Anthropic pages and the Google Cloud DORA blogs: every one of ~30 such figures reproduced verbatim (dates, wording, growth rates). The Stack Overflow, JetBrains, Gartner, Cursor, Codex and Anthropic-revenue figures also check out against secondary coverage, with three base/definition problems: (a) the SO 2024 "62% currently using" is stated by SO's own press release for *professional developers*, not all respondents (the note asserts the opposite); (b) SO 2023 trust is 48% in SO's press-release headline vs the note's ~42%; (c) the note treats "one in three pull requests on GitHub now involves an agent" as agent penetration of code output and uses "~30% of PRs involve agents" as the current level for a logistic extrapolation — but GitHub's own May 2026 wording ("more than one in five *code reviews* involve an agent", 60M Copilot code reviews) shows the metric counts review involvement, so it is not an authored-share figure. The note is stale in three places that matter: the SO 2025 "currently using" split exists (78%, per The New Stack's reading of the survey), the JetBrains May–Jul 2026 wave has a Claude Code figure (39% at work, 47% in the US), and Stack Overflow's May 2026 pulse survey gives an agent-use figure (59%, vs 31% in 2025). The China section contains no verified facts; this audit closes most of that gap below. The S-curve narrative (breadth saturated, intensity mid-curve, delegation exponential) is supported in direction; its "50% of PRs agent-involved in 2026–27" arithmetic is not, because of the definition issue above.

**ai_code_share_productivity.md (Note B).** The Anthropic-sourced material ([F]) is accurate: the Economic Index series, the internal-work study (59%/28%, +50%, 27%, 0–20% fully delegated), the skills RCT, the autonomy paper, the Sep 2026 "Claude authors 80%" post, prices and Sep 2026 benchmark scores all reproduced. The company-claim chronology (Google, Microsoft, Meta, Amazon, OpenAI, Coinbase, Robinhood, Salesforce, Spotify) is confirmed by top-tier press. The productivity table is broadly right but has one sign error that must be fixed: METR's Feb 2026 follow-up found returning developers 18% *faster* but newly recruited developers 4% *slower* (the note reads both as faster). Other corrections: Daniotti et al. is now published in Science with different numbers (29% of US Python functions, +3.6% quarterly output, 30M commits/170k developers) than the arXiv v1 numbers the note recalls; Stripe's Minions are ~1,300 PRs/week; Song et al. report +5.9% project contributions; the capability timeline omits Opus 4.7 (16 Apr 2026), Opus 4.8 (28 May 2026), Sonnet 4.6/5, and misdates Opus 5 (24 Jul 2026, not June; Fable 5/Mythos 5 were the June releases). The note's own GitHub PR-volume measurement reproduced exactly (781,708 vs 781,667; 167,813 exact; bot counts exact), but my added dependabot count shows bot PRs tripled over the same window, so the 4.7× rise is only partly attributable to coding agents. The "claims vs measurements" reasoning is sound and appropriately skeptical; the "capability overhang" inference leans on a disputed METR 16-hour horizon and should be softened.

## Definition and denominator warnings

1. **"Using or planning" ≠ "currently using" ≠ "daily".** SO's headline 70/76/84% includes planners; the currently-using series is 44% (2023) → 62% (2024) → 78% (2025, [S]); daily use was 51% of professional developers (2025). Planners shrank from 26 pp to ~6 pp, which is why the two series converge. Never splice 84% onto 44/62.
2. **Base of SO's 44%/62%.** SO's 2024 press release states both on the *professional-developer* base. Note A's instruction to treat 62% as all respondents should be reversed, or the base labelled "professional developers (per SO press release)".
3. **Two SO trust series.** Press-release series 48% (2023) → 43% (2024) → 33% (2025); the alternative 40% (2024) → 29% (2025) comes from a different question/base. Distrust 31% → 46%. Do not mix them in one line.
4. **DORA samples are "technology professionals"**, not only developers, and the 2024 metric is "rely on AI for at least one daily responsibility" whereas 2025 is "use AI at work". "39,000" is DORA's 10-year cumulative, not the 2024 sample.
5. **JetBrains definitions moved**: "regularly use ≥1 AI tool at work" (Jan 2026, 90%) vs "use AI coding agents at work at least weekly" (May–Jul 2026, 90%) — the latter counts agent modes inside IDEs and is a JetBrains-audience sample (heavy in East Asia and Java/Kotlin/Python). The two 90%s are not the same measure.
6. **Copilot "users" vs "paid subscribers" vs "organizations".** 15M/20M/26M/50M "users" include the Dec 2024 free tier (and press treated 20M as all-time); 4.7M paid subscribers (Jan 2026); ~140k organizations (Apr 2026). Report these on separate lines; never divide 50M by GitHub's 225M "users" as a paid-penetration rate.
7. **Run-rate vs ARR.** Anthropic ($14B/$30B/$47B/$65B), Claude Code ($0.5B/$1B/$2.5B) and Cursor figures are annualized run-rates from a recent period (often a week or month), not contracted ARR; the >$65B figure is press-sourced. Microsoft does not disclose Copilot revenue in dollars; "+60% QoQ" is a growth rate on an undisclosed base.
8. **"Share of code" — seven incompatible metrics.** (a) accepted-completion characters (Google Jun 2024 ~50%; Copilot 46% in enabled files); (b) "new code generated by AI then reviewed and accepted" (Google 25→30→50→75%, undefined unit); (c) "AI-assisted new code" (Tencent 50% of 2025 new code); (d) "authored by Claude" (Anthropic 80%, undefined); (e) classifier-detected AI functions in public Python (Daniotti 29% US); (f) commits with an attribution trailer (SemiAnalysis 4%, a floor); (g) self-reported share of own code (JetBrains distribution; Fastly). None is comparable across firms or years; company series (Google, Baidu, Tencent) are only comparable within the firm and only if the firm kept its metric, which none confirms.
9. **"Involves an agent" (GitHub, 1 in 3 PRs, Jul 2026)** includes agent code review (GitHub: >1 in 5 code reviews involve an agent, May 2026). Agent-*authored* shares observable from outside are far lower: bot-identity PRs 0.3–3% ([M]); Claude Code trailer commits 4% (Feb 2026). Do not use "1 in 3" as the current level of delegation.
10. **Bot-identity PRs vs human accounts.** [M] counts only PRs opened under app identities (copilot-swe-agent, devin, jules, claude app); Claude Code/Cursor/Codex CLI output is committed under the human's account. The Copilot-agent drop after Mar 2026 (77k → 16k/week) is uninterpretable (attribution/product changes, usage-based billing from 1 Jun 2026).
11. **PR-volume series includes automation growth.** Dependabot PRs tripled (33k → 99k/day) between the Sep 2024 and Sep 2026 sample days; totals include spam and reflect repo growth (+36M developers/yr). The 4.7× is indicative of agent-mediated volume, not a measure of it.
12. **Anthropic Economic Index "shares" are compositions of Claude traffic**, not adoption rates; Claude.ai vs 1P API are different populations; the Jan 2026 restatement changed the Jan 2025 split (57/43 → 55/41) because of an unclassified remainder; "coding migrated to the API" is partly a product effect (Claude Code splits work into many calls).
13. **CAICT "采纳率 42.61%"** is an acceptance rate of generated code, not the share of code written by AI; "nearly 70% of enterprises report >30% efficiency gains" is self-reported.
14. **Codex "20M active users" (Aug 2026)** has no window and may include ChatGPT Work; the WAU series ends at 8M (mid-Jul 2026).
15. **METR signs.** Jul 2025: +19% completion time (slower); Feb 2026: returning −18% time (faster), new recruits +4% time (slower). Always state direction in words.
16. **"AI share of work" (Anthropic 59%; OpenAI "99% of engineering work runs through Codex")** are self-reported/undefined and are not shares of code or of value.
17. **Gartner's metric** is sanctioned enterprise code assistants, so "hit 2028 target three years early" compares different measures; CAICT's "nearly 30% of enterprises with >90% AI-IDE penetration" shows enterprise-sanctioned penetration is high but not universal.

## Guidance for the report writer

**Robust conclusions (can be stated plainly, with the harmonized numbers above):**
1. Breadth of adoption saturated by 2025–26: currently-using 44% → 62% → 78% (SO, professional developers), DORA 76% → 90%, JetBrains 85% → 90%. The residual ~10% is policy-bound or refusers. Use the SO currently-using series, not the using-or-planning series, as the headline.
2. Adoption rose while stated trust fell (SO trust 48 → 43 → 33; distrust 31 → 46; favorable 77 → 72 → ~60); DORA's enterprise sample shows a small trust improvement (39% → 30% low/no trust). The decoupling of use from trust is well supported.
3. Modality shift to agents in 2025–26 is supported by four independent channels: SO agents 31% (mid-2025) → 59% (SO pulse, May 2026); JetBrains agents 90% weekly/68% daily and Claude Code 3% → 18% → 39% (Apr 2025 → Jan 2026 → mid-2026); Anthropic telemetry (coding migrating from Claude.ai to API; Claude Code 79% automation; p99.9 turn length doubling); GitHub (Copilot coding agent >1M PRs in 5 months; >1 in 5 code reviews with agents; 1 in 3 PRs "involving" an agent).
4. Seat metrics are giving way to consumption: Copilot paid 4.7M (+75% YoY) vs users 50M; usage-based billing from 1 Jun 2026 with revenue +60% QoQ; Claude Code/Cursor/Codex growth measured in run-rate and WAU. Paid-seat penetration cannot be computed from disclosed data — say so.
